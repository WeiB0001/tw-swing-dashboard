# 台股價差機會儀表板

每天收盤後自動掃描台股流動性最好的 100～150 檔個股，依「**現在進場的獲利可能性**」排名，找出 1～5 天的短線價差機會。排的不是技術指標最漂亮的，是進場位置與風險報酬最合理的。

裝到手機主畫面後就是一個 **app**：點開秒開、沒有網址列、捷運上沒訊號也看得到上次的結果。不用輸入任何東西，不用登入，不用付費。

> ⚠️ 本工具僅供個人技術分析參考，不構成任何投資建議，投資有風險。

---

## 安裝：跑一個檔案就好

### 第一步 · 執行安裝程式

| 你的電腦 | 做法 |
|---|---|
| **Mac** | 雙擊 `setup.command`（若說「無法打開」，按住 Control 點檔案 → 打開 → 再按一次打開） |
| **Windows** | 雙擊 `setup.bat` |
| 都不行 | 開終端機，`cd` 到這個資料夾，執行 `python3 install.py` |

> Mac 上雙擊 `setup.command` 如果是用文字編輯器打開，代表解壓縮時掉了執行權限。在終端機到這個資料夾執行一次 `chmod +x setup.command` 就好，或直接跑 `python3 install.py`。

> 沒有 Python？到 <https://www.python.org/downloads/> 下載安裝，Windows 安裝時記得勾 **Add Python to PATH**。

### 第二步 · 貼上權杖

程式一開始就會問，直接貼上按 Enter 即可（**畫面不會顯示你貼的內容，這是正常的**）。

已經有權杖的話，也可以完全跳過互動：

```bash
python3 install.py --token ghp_你的權杖
python3 install.py --token ghp_你的權杖 --repo 我的儀表板
# 或用環境變數
GITHUB_TOKEN=ghp_你的權杖 python3 install.py
```

**還沒有權杖？** 到 <https://github.com/settings/tokens/new?scopes=repo,workflow> 按最下面的 **Generate token**，複製 `ghp_` 開頭那串就好（權限已預先勾選）。沒有 GitHub 帳號的話先到 <https://github.com/signup> 註冊，兩分鐘。

### 第三步 · 等它跑完

程式會自動建 repo、上傳、開好設定、抓今天的資料，大約 3～6 分鐘。跑完會直接給你網址，長這樣：

```
https://你的帳號.github.io/tw-swing-dashboard/
```

網址也會存成 `我的儀表板網址.txt` 放在同一個資料夾，不怕弄丟。

### 第四步 · 變成手機 app

用手機打開那個網址，加到主畫面：

- **iPhone**：用 Safari 打開 → 按下方中間的「分享」→ 往下捲找到「加入主畫面」
- **Android**：用 Chrome 打開 → 網址列旁的選單 → 「安裝應用程式」

主畫面就會多一個圖示。之後每個交易日 16:20 和 18:00 自動更新，**你什麼都不用做**，早上通勤時點開就是最新的。

## 上班時間怎麼用

這個工具的定位是**收盤後選出隔天的觀察清單**，不是盤中即時訊號。實務上的節奏：

- 第一次打開時，在最上方那個面板填一次「本週預算」、選好「分散成幾檔」「每張預算」「產業」，之後每次開啟都會自動套用，不用再輸入
- 昨天 16:20 之後（或今天早上通勤）點開 app，看前幾名
- 頁面上會寫「3 小時前更新」，一眼就知道資料多新
- 想看細節就點卡片展開，不想看就只看分數和一行理由
- 沒訊號的日子頁面會直接說「今天沒有達標的標的」，不會硬湊給你看

排名上方是一個合併的控制面板：本週預算、分散檔數、每張預算、產業，全部在同一個框裡，改任何一項都會即時重算。

**本週預算試算**：填入這週能動用的金額、選要分散成幾檔，每張卡片的獲利可能性分數正下方就會顯示「本週配置 NT$34,412 · 零股 922 股」，下方也會算出實際可投入與剩餘現金。演算法是把預算按獲利可能性分數的比例拆分，單一標的上限 45%（只選 1 檔時自動放寬），不足一張時改算零股。這純粹是算術，不是建議你買進，也沒計手續費與證交稅。

台股一張是 1000 股，所以一股 2000 元的股票，一張要 200 萬。卡片上直接寫「一張 X 萬」，不用自己乘。預算按鈕只影響顯示、不影響排名——名次維持全市場的原始名次，所以你會看到第 3、第 7、第 12 名這樣跳號，那是正常的。

如果 app 顯示的是手機快取的舊資料，頁面上方會自動跳出「已有新的收盤資料」，點一下重新載入就好。沒網路時也會明確告訴你「目前離線，顯示的是上次載入的資料」，不會讓你誤把舊資料當今天的。

## 分數怎麼算

排名回答的**不是**「哪檔技術指標最漂亮」，而是：

> 以目前價格進場，在合理的 Swing 持有期間內，哪一檔最可能產生正報酬，而且風險報酬比最好？

因此**趨勢強度**與**進場位置**是分開計算的兩件事。一檔 RSI 90、貼著前高的股票，趨勢分數會滿分，但位置分數很低、風險分數很高，不會自動排第一。

### 三層結構

```
機會分數 Opportunity = 位置 25 + 趨勢 20 + 轉強 15 + 量價 15 + 風報 15  →  正規化為 0～100
風險分數 Risk        = 過熱 + 追高 + 乖離 + 連漲 + 假突破 + 未止跌      →  0～100
獲利可能性 PPS       = Opportunity × (1 − 0.35 × Risk/100)
```

| 項目 | 權重 | 內容 | 加分 | 扣分 |
|---|---|---|---|---|
| **位置** | 25 | 20 日區間位置、距 20／60 日高點空間、距 MA20 乖離、RSI 區帶 | 位於區間中下緣、距前高仍有 6% 以上空間、乖離 −9%～+4% | 區間位置 > 88%、距前高 < 1.5%、正乖離過大 |
| **趨勢** | 20 | MA5/10/20/60 排列、MA20 與 MA60 斜率、是否站穩季線 | 多頭排列、均線同步向上 | 空頭排列、均線下彎 |
| **轉強** | 15 | RSI 自低檔回升、站回 MA5、MA5 上彎／金叉、MACD 柱改善、帶量收紅、低點未再破 | 訊號越多分越高 | 一個都沒有就是 0 分 |
| **量價** | 15 | 量能倍數 × **品質係數** | 上漲帶量且收在當日高檔、有效突破、上漲日均量 > 下跌日 | 長上影 ×0.55、爆量收黑 ×0.25、再跌破均線 ×0.4、高檔爆量 ×0.45 |
| **風報** | 15 | 以 20／60 日高點與 ATR 推估上檔、以 MA20／近期低點／ATR 推估下檔 | 風險報酬比 ≥ 2.5、上檔空間 ≥ 7.5% | 比值 < 1、空間 < 3% |

### 風險分數的組成

| 風險項目 | 相對權重 | 觸發條件 |
|---|---|---|
| RSI 過熱 | 0.22 | RSI > 75（92 時滿分） |
| 追高（距前高太近） | 0.14 | 距 20 日高 < 3%（**有效突破時減半**） |
| 已離低點太遠 | 0.10 | 距 20 日低 > 30% |
| 乖離 MA20 過大 | 0.16 | 正乖離 > 10% |
| 短期漲幅過大 | 0.12 | 近 5 日 > 12% 或連 4 日紅 |
| 假突破 | 0.16 | 突破但量能不足／長上影／收盤未守高／RSI 過熱 |
| 跌深未止跌 | 0.20 | 均線空頭排列且收盤在 MA5 下，或今日再創 20 日新低 |

**有效突破**（突破前 20 日高 + 量 ≥ 1.3 倍 + 收盤在當日高檔 + 無長上影 + RSI < 75）不套用追高懲罰，位置分數另有 0.7 的保底——這是「突破型賺錢機會」，不是追高。

### 排序與 tie-breaker

主鍵是獲利可能性分數。分數相近（1.5 分內）時依序比較：
歷史相似訊號勝率 → 風險報酬比 → 下檔風險 → 進場位置 → 趨勢品質。
所以名次未必與四捨五入後的分數完全同序，這是刻意的。

### ⚠️ 分數不是機率

`獲利可能性 73` 的意思是「這個模型認為此時進場的條件相對好」，**不是「73% 會賺錢」**。

只有跑過 `python scripts/backtest.py` 產生 `data/backtest.json` 之後，卡片上才會另外出現「歷史相似訊號勝率 68%（樣本 240 筆）」——那才是統計數字，且仍不代表未來績效。沒跑過回測時，頁面不會出現任何百分比勝率。

## 回測：驗證分數到底有沒有預測力

```bash
python scripts/backtest.py --days 250      # 回測最近 250 個交易日
python scripts/backtest.py --demo          # 用模擬資料驗證程式流程（不會寫入結果）
```

做法是逐日重跑一次當天的流程：用「只到當天為止」的資料算分數（嚴格不用未來資料），取前 K 名，計算持有 3／5／10／20 天的結果。輸出：

- Top 1／3／5／10 以及「全部達標訊號」的勝率、平均報酬、中位數報酬、最大虧損、平均與最差回撤、盈虧比、Profit Factor
- 分數級距 vs 持有 5 日勝率（這是卡片上「歷史相似訊號勝率」的來源）

**要看的是排名有沒有鑑別力**：如果 Top 1 的勝率和平均報酬明顯高於 Top 10、Top 10 又高於全部訊號，才代表「排第一比排第十值得買」。如果三者差不多，就是排名沒用，該回頭調 `config.py` 的權重。

`.github/workflows/backtest.yml` 每週日自動跑一次並提交結果，你不用手動處理。

## 要改訊號邏輯的話

**九成的調整只要改 `scripts/config.py` 一個檔案。** 每個參數都註明了改大改小的效果。

| 想做的事 | 改哪裡 |
|---|---|
| 訊號太少／太多 | `MIN_SCORE_TO_SHOW` |
| 更重視進場位置 | `WEIGHTS["entry"]` 調高，其他等比調低 |
| 追高懲罰太重／太輕 | `RISK_MAX_CUT`（0.35 = 最多打 65 折；設 0.10 回到純加權） |
| 更早／更晚判定過熱 | `RSI_HOT`、`NEAR_HIGH_PCT`、`BIAS20_WARN` |
| 突破股要更寬鬆 | `BREAKOUT_POS_FLOOR`、`VOL_SURGE_RATIO` |
| 高價股連掃都不想掃 | `MAX_CLOSE_PRICE`（每股上限，0 = 不限） |
| 改預算按鈕的級距 | `PRICE_BANDS`、`DEFAULT_PRICE_BAND` |
| 改本週預算快選金額 | `BUDGET_PRESETS` |
| 改單一標的上限／預設檔數 | `MAX_POSITION_PCT`、`DEFAULT_SPLITS` |
| 不想用零股試算 | `ALLOW_ODD_LOT = False` |
| 增減電子科技股 | `TECH_SECTORS`（加一行 `"代號": "產業"`） |
| 掃描池上限 | `MAX_UNIVERSE`（目前 220） |
| 只看大型股 | `MIN_TURNOVER_TWD` 調高、`TOP_N_BY_TURNOVER` 調低 |
| 多顯示幾檔 | `TOP_N_DISPLAY` |
| 換掃描池 | `CORE_WEIGHTED_STOCKS` |

要改判斷方式（不只是門檻），改 `scripts/scoring.py` 裡對應的 `_score_xxx` 函式。每個都獨立回傳 `(強度 0~1, 中文理由)`，新增一項成分只要照同格式寫一個函式，加進 `score_stock()` 的 `comp` 並在 `config.WEIGHTS` 給權重即可。風險項目則加在 `_risk_score()` 與 `config.RISK_WEIGHTS`。

改完先在本機驗證，不用等收盤：

```bash
pip install -r requirements.txt
python scripts/build.py --demo   # 用模擬資料產生 index.html，不連網
```

確認沒寫壞之後，把改動推回 GitHub（或重新跑一次 `install.py`），下一次排程就會生效。

## 資料來源

掃描池 = 當日成交金額前 100 名 + 主要權值股 + **電子／科技類上市公司 85 檔**（半導體、IC 設計、封測、記憶體、PCB／載板、被動元件、電腦週邊、工業電腦、散熱機構、網通、光電面板、光學、電子通路、電信、設備儀器）。這些科技股一律納入，不必等它們擠進成交金額排行，但仍要通過股價與成交金額門檻，避免掃到掛單掛不掉的冷門股。卡片上會標示產業別，面板上可以切「電子科技／非電子」。

要增減關注的個股，改 `scripts/config.py` 的 `TECH_SECTORS`，加一行 `"代號": "產業"` 就好。

1. **證交所 OpenAPI**（`openapi.twse.com.tw`）— 當日全市場行情，決定掃描池與當日價量。免費、免金鑰。
2. **yfinance** — 歷史日線（代號加 `.TW`），用來算指標。
3. **FinMind**（選用）— 只有在 repo Secrets 設了 `FINMIND_TOKEN` 才啟用，用來補 yfinance 抓不到的個股。不設也能正常運作。

yfinance 收盤後偶爾延遲一天更新，程式會用證交所的當日資料覆寫最後一根 K 棒，確保訊號用的是今天的價量。

## 常見狀況

**安裝程式說權杖無效？** 權杖只會顯示一次，關掉頁面就看不到了。重新產生一個再貼，並確認網址列有帶 `scopes=repo,workflow`。

**出現「Git Repository is empty.」？** 這是舊版安裝程式的問題，已修正。用新的檔案重跑一次，遇到「repo 已經存在」按 `y` 沿用即可。

**Mac 雙擊說「無法打開，因為來自未識別的開發者」？** 按住 Control 點 `setup.command` → 選「打開」→ 再按一次「打開」。只需要做一次。

**Actions 跑失敗了？** 程式在失敗時**不會覆寫 `index.html`**，你打開網頁還是會看到上一次成功的結果。到 repo 的 Actions 分頁看 log，多半是資料來源暫時異常，等下一次排程通常就好了。

**選了預算之後一檔都不剩？** 表示今天入選的標的都超過你的預算。可以改選寬一點的區間，或把 `config.py` 的 `MAX_CLOSE_PRICE` 設成你的每股上限（例如 `100`），這樣連掃描階段就只會看低價股，排進來的自然都買得起。

**頁面說「今天沒有達標的標的」？** 這不是壞掉。大盤普漲時本來就找不到超賣反彈的標的，這個策略在盤整或回檔後的第一根反彈最容易出訊號。

**排程沒有準時？** GitHub 的排程在尖峰時段可能延遲 5～20 分鐘，屬正常現象。頁面上的「交易日」欄位會告訴你資料實際是哪一天的。

**為什麼 repo 一定要 public？** GitHub Pages 免費方案只支援公開 repo。裡面沒有任何私人資料，只有程式碼和公開行情。

**只掃上市股票？** 是的。證交所 OpenAPI 的 `STOCK_DAY_ALL` 只涵蓋上市，程式也只取 4 碼純數字代號（排除 ETF、權證、特別股）。要加上櫃股票需要另外接櫃買中心的 API。

**能改成盤中更新嗎？** 可以，但不建議。GitHub 排程有延遲、免費資料源也有延遲，盤中訊號會失真。

## 不想用安裝程式的話

手動部署也可以：推 repo → Settings / Pages 的 Source 選 **GitHub Actions** → Settings / Actions / General 選 **Read and write permissions** → Actions 分頁手動 **Run workflow**。`install.py` 做的就是這四件事。
