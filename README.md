# 台股價差機會儀表板

每天收盤後自動掃描台股流動性最好的 100～150 檔個股，依「**現在進場的獲利可能性**」排名，找出 1～5 天的短線價差機會。排的不是技術指標最漂亮的，是進場位置與風險報酬最合理的。

裝到手機主畫面後就是一個 **app**：點開秒開、沒有網址列、捷運上沒訊號也看得到上次的結果。不用輸入任何東西，不用登入，不用付費。

> ⚠️ 本工具僅供個人技術分析參考，不構成任何投資建議，投資有風險。

程式會自動建 repo、上傳、開好設定、抓今天的資料，大約 3～6 分鐘。跑完會直接給你網址，長這樣：

網址也會存成 `我的儀表板網址.txt` 放在同一個資料夾，不怕弄丟。

## 上班時間怎麼用

這個工具的定位是**收盤後選出隔天的觀察清單**，不是盤中即時訊號。實務上的節奏：

- 第一次打開時，在最上方填一次「本週預算」，之後每次開啟都會自動套用，不用再輸入
- 昨天 16:20 之後（或今天早上通勤）點開 app，看前幾名
- 頁面上會寫「3 小時前更新」，一眼就知道資料多新
- 想看細節就點卡片展開，不想看就只看分數和一行理由
- 沒訊號的日子頁面會直接說「今天沒有達標的標的」，不會硬湊給你看

**只有一個預算欄位**。填了本週預算之後，一張買不起的標的會自動從清單消失——不用再另外挑價位區間。

**配置有兩種方式**：

- **自動分配**：取顯示中的前 N 檔，按獲利可能性分數比例拆分預算，單一標的上限 45%（只選 1 檔時放寬）
- **自己挑**：點卡片上的「＋ 選入」把想買的加進來，預算會在你選的標的之間平均分配。選過的當天會記住，換一天的資料自動清空

兩種方式的結果都會顯示在卡片的獲利可能性分數正下方「本週配置 NT$34,412 · 零股 922 股」，下方也會算出實際可投入與剩餘現金。演算法是把預算按獲利可能性分數的比例拆分，單一標的上限 45%（只選 1 檔時自動放寬），不足一張時改算零股。這純粹是算術，不是建議你買進，也沒計手續費與證交稅。

台股一張是 1000 股，所以一股 2000 元的股票，一張要 200 萬。卡片上直接寫「一張 X 萬」，不用自己乘。預算按鈕只影響顯示、不影響排名——名次維持全市場的原始名次，所以你會看到第 3、第 7、第 12 名這樣跳號，那是正常的。

如果 app 顯示的是手機快取的舊資料，頁面上方會自動跳出「已有新的收盤資料」，點一下重新載入就好。沒網路時也會明確告訴你「目前離線，顯示的是上次載入的資料」，不會讓你誤把舊資料當今天的。

## 排名依據：歷史勝率，不是技術分數

首頁名次的第一順位是**歷史平滑勝率**。做法是先用技術面把每檔標的歸類成「型態 ＋ 分數級距」（例如「帶量突破 ＋ 65–75 分」），再去回測資料裡查同一類訊號歷史上贏過幾次。

```
排序順位：期望值 EV → 平滑勝率 → Profit Factor → 平均最大回撤 → 技術分數
EV = 勝率×平均獲利 + 敗率×平均虧損（已扣 0.3% 成本）
勝率平滑：(勝場 + 10) / (樣本 + 20)      ← 避免「3 戰 3 勝 = 100%」
查表順序：大盤狀態+型態+級距 → 型態+級距 → 級距 → 樣本不足
可信度：N<30 樣本不足 / 30–59 ★★ / 60–119 ★★★ / 120–249 ★★★★ / ≥250 ★★★★★
```

**EV ≤ 0 的標的會降到有正 EV 的之後，但不刪除**——看得到名次，只是排在後面。

### 大盤狀態（Market Regime）

依加權指數判定：`bull`（收盤 > MA20 > MA60 且 MA20 斜率 > 0）、`bear`（收盤 < MA20 且斜率 < 0）、其餘 `sideways`。首頁標題旁顯示 🟢 多頭 / 🟡 震盪 / 🔴 空頭。同一個型態在多頭與空頭的勝率差很多，所以回測查表的第一層就是大盤狀態。

**樣本不足就說樣本不足。** 型態層需 30 筆，不足退回只看分數級距（也需 30 筆），再不足就標示「樣本不足」，以先驗 50% 計入排名並改用技術分數決定先後。**不會生一個假勝率出來。**

還沒跑過回測時，所有標的都是「樣本不足」，名次等於只由技術分數決定——頁面會明講這件事。

### 技術分數（0～100）只是分層特徵

它描述「當下的價量型態長什麼樣」，不是獲利機率。機會分數（五項加權正規化）× 風險調整：

| 項目 | 權重 | 內容 |
|---|---|---|
| 位置 | 25 | 20 日區間位置、距 20／60 日高點空間、MA20 乖離、RSI 區帶 |
| 趨勢 | 20 | MA5/10/20/60 排列與斜率、是否站穩季線 |
| 轉強 | 15 | RSI 自低檔回升、站回 MA5、金叉、MACD 柱改善、帶量收紅 |
| 量價 | 15 | 量能倍數 × 品質係數（長上影、爆量收黑、高檔爆量大幅打折） |
| 風報 | 15 | 以高點與 ATR 推估上檔，以 MA20、近期低點與 ATR 推估下檔 |

風險調整：過熱、追高、乖離、連漲、假突破、未止跌，最多打 65 折。有效突破不套用追高懲罰。

## 回測：排名的資料來源

```bash
python scripts/backtest.py --days 250      # 回測最近 250 個交易日
python scripts/backtest.py --demo          # 用模擬資料驗證流程（不會寫入結果）
```

**交易假設刻意保守：**

| 項目 | 設定 | 為什麼 |
|---|---|---|
| 進場價 | **t+1 開盤價** | 訊號是 t 日收盤後算出來的，用 t 日收盤價當進場價等於偷看 |
| 出場價 | t+h 收盤價 | |
| 交易成本 | 來回 **0.3%** | 手續費＋證交稅，`TRADE_COST_PCT` 可調（實務約 0.4～0.6%） |
| 勝敗判定 | **淨報酬 > 0** 才算贏 | 扣完成本還賺才是賺 |
| 訊號冷卻 | 同股票 **5 個交易日** 內不重複採樣 | 否則同一段行情會被算成好幾個獨立樣本，樣本數灌水 |
| 主要持有期 | 5 日 | 同時保留 3／10／20 日 |

每組輸出：samples、calibrated_win_rate、avg_net_return、avg_win、avg_loss、profit_factor、MDD、**expectancy**。

分層統計：分數級距 / 型態 × 級距 / **大盤狀態 × 型態 × 級距**（排名查表的第一順位）。

### Walk-forward（out-of-sample）

樣本依時間切 4 段，第 1 段只建表，之後每段都只用「該段之前」的資料建表再測——不用測試期間的資料調自己。每日取期望值最高的前 3 檔且 EV > 0，記錄實際 5 日淨報酬。首頁顯示一行 `Walk-forward：EV X% · PF X.XX · N XXX`，樣本不足就顯示「資料不足」，不製造結果。

只用 numpy／pandas，沒有額外套件。

`.github/workflows/backtest.yml` 每週日自動跑並提交結果。

**要看的是排名有沒有鑑別力**：Top 1 的勝率與平均淨報酬要明顯高於 Top 10，Top 10 又要高於全部訊號。三者差不多就是排名沒用，該回頭調 `config.py` 的權重。

## 明日交易計畫

每檔候選股自動產生純規則的計畫（沿用既有 ATR、MA、支撐壓力，沒有新模型）：

- **狀態**：可觀察進場 / 等待確認 / 禁止追價（過熱、貼前高、乖離過大 → 禁止追價）
- **觸發價**：今日高點 + 0.05 ATR
- **失效價**：今日低點 − 0.05 ATR（跌破代表型態不成立）
- **停損**：支撐與失效價取較低，並限制在 3 ATR 內
- **目標一／目標二**：近壓與 ATR 投射，目標一保證高於觸發價
- **RR**：(目標一 − 觸發價) / (觸發價 − 停損)

價位是算術換算，不保證成交也不保證獲利。

## 美股連動：推估隔日方向

時序要先講清楚，不然很容易做出偷看未來的假模型：

```
台股 8/22 盤中  →  美股 8/22 盤（台北 8/23 04:00 收）  →  台股 8/23
```

影響台股某一天的是**前一晚的美股**。但這支程式在台北 16:20 執行時，今晚的美股還沒開始。所以：

1. 用「已收盤的前一夜美股」與台股跑迴歸（最小平方法，只用 numpy）：
   `台股報酬 ≈ a + b×那斯達克 + c×費半`
2. 用「此刻正在交易的美股期貨」（NQ=F、ES=F 幾乎 24 小時交易）當作今晚方向的即時代理，代入迴歸式

頁面會一併顯示 R² 與樣本數。**R² 低於 0.05 就直接不顯示推估值**——關聯性太弱時講了反而誤導。R² 0.38 的意思是美股只能解釋台股約 38% 的波動，其餘來自台股自己的籌碼與消息面。

UI 以燈號為主（🟢 偏多 / 🟡 中性 / 🔴 偏空），中央估計、預測區間與 R² 縮成小字。**這個燈號不參與個股排序**——排名以大盤狀態與歷史 EV 為準。

這是統計相關性外推，不是預測。抓不到資料時整個區塊會自動省略，不影響主流程。關掉：`US_ENABLED = False`。

## 要改訊號邏輯的話

**九成的調整只要改 `scripts/config.py` 一個檔案。** 每個參數都註明了改大改小的效果。

| 想做的事 | 改哪裡 |
|---|---|
| 訊號太少／太多 | `WEAK_SCORE`（低於此分數標示「訊號偏弱」，但仍列出、仍佔名次） |
| 一頁先顯示幾筆 | `INITIAL_VISIBLE` |
| 交易成本假設 | `TRADE_COST_PCT` |
| 訊號冷卻天數 | `SIGNAL_COOLDOWN_DAYS` |
| 勝率平滑力道 | `SMOOTH_WINS`、`SMOOTH_N` |
| 型態樣本門檻 | `PATTERN_MIN_SAMPLES` |
| 關掉美股區塊 | `US_ENABLED = False` |
| 更重視進場位置 | `WEIGHTS["entry"]` 調高，其他等比調低 |
| 追高懲罰太重／太輕 | `RISK_MAX_CUT`（0.35 = 最多打 65 折；設 0.10 回到純加權） |
| 更早／更晚判定過熱 | `RSI_HOT`、`NEAR_HIGH_PCT`、`BIAS20_WARN` |
| 突破股要更寬鬆 | `BREAKOUT_POS_FLOOR`、`VOL_SURGE_RATIO` |
| 高價股連掃都不想掃 | `MAX_CLOSE_PRICE`（每股上限，0 = 不限） |
| 改本週預算快選金額 | `BUDGET_PRESETS` |
| 改單一標的上限／預設檔數 | `MAX_POSITION_PCT`、`DEFAULT_SPLITS` |
| 不想用零股試算 | `ALLOW_ODD_LOT = False` |
| 增減電子科技股 | `TECH_SECTORS`（加一行 `"代號": "產業"`） |
| 增減 ETF | `TW_ETFS` |
| 要掃槓桿／反向／債券 ETF | `ETF_ALLOW_LEVERAGED = True` |
| 完全不掃 ETF | `INCLUDE_ETF = False` |
| 買不起的不要隱藏 | `HIDE_UNAFFORDABLE = False` |
| 掃描池上限 | `MAX_UNIVERSE`（目前 220） |
| 只看大型股 | `MIN_TURNOVER_TWD` 調高、`TOP_N_BY_TURNOVER` 調低 |
| 多顯示幾檔 | `TOP_N_DISPLAY` |
| 換掃描池 | `CORE_WEIGHTED_STOCKS` |

要改判斷方式（不只是門檻），改 `scripts/scoring.py` 裡對應的 `_score_xxx` 函式。每個都獨立回傳 `(強度 0~1, 中文理由)`，新增一項成分只要照同格式寫一個函式，加進 `score_stock()` 的 `comp` 並在 `config.WEIGHTS` 給權重即可。風險項目則加在 `_risk_score()` 與 `config.RISK_WEIGHTS`。

改完先在本機驗證，不用等收盤：

```bash
pip install -r requirements.txt
python scripts/build.py --demo   # 用模擬資料產生 index.html，不連網
```

確認沒寫壞之後，把改動推回 GitHub（或重新跑一次 `install.py`），下一次排程就會生效。

## 資料來源

掃描池 = 當日成交金額前 100 名 + 主要權值股 + **電子／科技類上市公司 85 檔** + **台股 ETF 35 檔**（市值型、高股息、科技主題、金融、主題型）（半導體、IC 設計、封測、記憶體、PCB／載板、被動元件、電腦週邊、工業電腦、散熱機構、網通、光電面板、光學、電子通路、電信、設備儀器）。這些科技股一律納入，不必等它們擠進成交金額排行，但仍要通過股價與成交金額門檻，避免掃到掛單掛不掉的冷門股。卡片上會標示產業別，面板上可以切「電子科技／非電子」。

ETF 的槓桿型（00631L）、反向型（00632R）、債券型（00679B）**預設排除**，因為這類商品的技術訊號跟一般股票不是同一回事。要放行改 `ETF_ALLOW_LEVERAGED = True`。

要增減關注的標的：個股改 `TECH_SECTORS`、ETF 改 `TW_ETFS`，各加一行 `"代號": "分類"` 就好。

1. **證交所 OpenAPI**（`openapi.twse.com.tw`）— 當日全市場行情，決定掃描池與當日價量。免費、免金鑰。
2. **FinMind**（`TaiwanStockPrice`）— **台股歷史日線的唯一來源**。欄位對應：`max→high`、`min→low`、`Trading_Volume→volume`。
3. **yfinance** — 只留給美股指數、美股期貨與加權指數，不再負責台股個股歷史。

### 歷史資料快取

每檔股票存成 `data/history/{股票代號}.csv`，掃描（`build.py`）與回測（`backtest.py`）**共用同一份**，不會各自重抓：

- 第一次抓最近 14 個月日線
- 之後只抓「快取最後一天之後」的新資料，合併後依日期去重、排序
- 快取已是最新就完全不打 API
- 請求間隔 0.2～0.5 秒；遇 429／5xx 指數退避重試（1→2→4→8→16 秒，最多 5 次）
- FinMind 失敗 → 用既有快取頂著，不讓 Actions 失敗
- FinMind 查無資料 → 記下代號跳過，不影響其他股票

`FINMIND_TOKEN` 從環境變數讀取，**沒有 token 也能用免費額度**（只是比較慢）。要加的話到 repo Settings → Secrets → Actions 新增 `FINMIND_TOKEN`。

CSV 不進版控（`.gitignore` 已排除），改由 GitHub Actions 的 `actions/cache` 在每次 workflow 之間保存與還原，所以不會每天重抓 14 個月。

yfinance 收盤後偶爾延遲一天更新，程式會用證交所的當日資料覆寫最後一根 K 棒，確保訊號用的是今天的價量。

## 常見狀況

**安裝程式說權杖無效？** 權杖只會顯示一次，關掉頁面就看不到了。重新產生一個再貼，並確認網址列有帶 `scopes=repo,workflow`。

**出現「Git Repository is empty.」？** 這是舊版安裝程式的問題，已修正。用新的檔案重跑一次，遇到「repo 已經存在」按 `y` 沿用即可。

**Mac 雙擊說「無法打開，因為來自未識別的開發者」？** 按住 Control 點 `setup.command` → 選「打開」→ 再按一次「打開」。只需要做一次。

**Actions 跑失敗了？** 程式在失敗時**不會覆寫 `index.html`**，你打開網頁還是會看到上一次成功的結果。到 repo 的 Actions 分頁看 log，多半是資料來源暫時異常，等下一次排程通常就好了。

**填了預算之後一檔都不剩？** 表示今天入選的標的，每一檔一張都超過你的預算。可以提高預算、切到 ETF 類別（ETF 一張通常兩三萬就有），或把 `config.py` 的 `MAX_CLOSE_PRICE` 設成你的每股上限（例如 `100`），這樣連掃描階段就只會看低價股，排進來的自然都買得起。

**頁面說「今天沒有達標的標的」？** 這不是壞掉。大盤普漲時本來就找不到超賣反彈的標的，這個策略在盤整或回檔後的第一根反彈最容易出訊號。

**排程沒有準時？** GitHub 的排程在尖峰時段可能延遲 5～20 分鐘，屬正常現象。頁面上的「交易日」欄位會告訴你資料實際是哪一天的。

**為什麼 repo 一定要 public？** GitHub Pages 免費方案只支援公開 repo。裡面沒有任何私人資料，只有程式碼和公開行情。

**只掃上市股票？** 是的。證交所 OpenAPI 的 `STOCK_DAY_ALL` 只涵蓋上市，程式也只取 4 碼純數字代號（排除 ETF、權證、特別股）。要加上櫃股票需要另外接櫃買中心的 API。

**能改成盤中更新嗎？** 可以，但不建議。GitHub 排程有延遲、免費資料源也有延遲，盤中訊號會失真。

## 不想用安裝程式的話

手動部署也可以：推 repo → Settings / Pages 的 Source 選 **GitHub Actions** → Settings / Actions / General 選 **Read and write permissions** → Actions 分頁手動 **Run workflow**。`install.py` 做的就是這四件事。
